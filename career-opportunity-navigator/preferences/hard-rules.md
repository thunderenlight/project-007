# Hard Rules — Non-Negotiable Career Decision Filters

These rules override the scoring framework. A high-scoring opportunity that breaks a hard rule must be re-evaluated or declined.

**Last Updated:** 2026-07-27

---

## Rule 1 — The Build Test

**Rule:** Every accepted opportunity must include the opportunity to build something.

**Acceptable building:**
- Writing code in any language
- Architecting a cloud solution
- Designing and deploying an API
- Building a product prototype
- Creating an AI-powered tool
- Reviewing code in a technical capacity

**Not acceptable as substitutes:**
- Requirements documents only
- Governance and compliance frameworks only
- Stakeholder communication and coordination only
- Dashboard maintenance with no growth path
- Status reporting only

**Exception:** A role can pass this rule if it provides direct access to engineers building the above AND includes a documented path to participate in the build within 30 days.

**Why this rule exists:** Career skills compound. Every year spent not building makes starting harder. Every year spent building makes continuing easier. The longer you delay, the more the gap grows.

---

## Rule 2 — The 3-Year Test

**Rule:** Before accepting, ask: Will this experience make me meaningfully more valuable in 3 years?

Specifically — after this role, will you be able to say:
- "I have a technical skill that employers specifically want"
- "I shipped something I can show"
- "I worked on a team I can credibly reference"

If two or more of these are "No," the role scores low on Marketability and Learning Potential by definition, and should be flagged.

**Why this rule exists:** Short-term availability is easy to fill. Long-term trajectories are built deliberately or not at all. A role that solves a 6-month cash flow problem but sets back a 3-year goal is a net negative.

---

## Rule 3 — The Anti-Pattern Limit

**Rule:** Do not accept more than one consecutive role that matches a career anti-pattern.

**Anti-patterns:**
- PMO administration
- Status reporting without building
- Governance without implementation
- Resource tracking
- Dashboard maintenance (no technical growth path)

**Consequence:** If the previous role was an anti-pattern, the next role MUST score 60+ on the evaluation framework. No exceptions.

**Why this rule exists:** Two consecutive anti-pattern roles do not just waste time — they actively signal to future employers that this is your trajectory. Three consecutive anti-pattern roles create a story that is very hard to rewrite.

---

## Rule 4 — The Technology Filter

**Rule:** Strongly prefer opportunities that include at least 2 of these:

- AWS (any hands-on service usage)
- React or TypeScript
- Python or FastAPI
- AI/ML implementation (not governance)
- GitHub with real code commits
- APIs (building or deeply integrating)

Opportunities missing all 6 should score below 30 on the evaluation framework unless exceptionally strong in Leadership, Product Ownership, and Compensation dimensions.

**Why this rule exists:** Market demand for the target technology stack is what makes this career path viable. Each technology you can credibly claim expands the pool of roles you qualify for. Roles that teach no target technologies have an opportunity cost measured in months.

---

## Rule 5 — The Positioning Test

**Rule:** After this role, you must be able to answer "What can you build?" with a specific, tangible example.

**Strong answer:** "I built [X] using [Y technologies] on [Z platform], which produced [business outcome]."

**Weak answer:** "I managed the delivery of [X] and coordinated the [Y] workstream."

If the role cannot produce the strong-answer version, it scores low on Portfolio Value by definition.

**Why this rule exists:** Target roles — AI PM, AI Platform Lead, Agentic Systems Lead — require hybrid credibility. Interviewers will ask "what have you built?" If the answer is always coordination-focused, the door to technical product leadership stays closed.

---

## Rule 6 — The Engineering Credibility Test

**Rule:** The role should improve your standing with technical hiring managers, not just business stakeholders.

Ask: After this role, could a senior software engineer take my resume seriously for a technical product role?

If no — it scores below 5 on Engineering Proximity by definition.

**Why this rule exists:** The gap between "I coordinate engineers" and "I work alongside engineers on technical problems" is enormous in hiring. Roles that build engineering credibility open Tier 1 and Tier 2 target roles. Roles that do not build it only open Tier 3 and below.
