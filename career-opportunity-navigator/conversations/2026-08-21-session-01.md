## 2. Dashboard KPI Animation Fix

**Decision:** Fix the KPI animation conflict. User approved.

**Root cause:** `.kpi` tiles had `class="kpi t reveal"`. The `.reveal` CSS class sets `opacity:0`. GSAP runs `gsap.from('.kpi', { opacity:0, y:16 })` — which animates FROM `opacity:0` TO the element's natural state. But the natural state was also `opacity:0` (from `.reveal`). Both animation endpoints were the same value: invisible.

**Fix applied:** Removed `reveal` class from all four KPI tile divs (lines 341, 346, 351, 356 in the HTML).

```html
<!-- Before -->
<div class="kpi t reveal">
<div class="kpi p reveal">
<div class="kpi g reveal">
<div class="kpi gr reveal">

<!-- After -->
<div class="kpi t">
<div class="kpi p">
<div class="kpi g">
<div class="kpi gr">
```

GSAP now has sole control over tile entrance animation. The `kpiObs` IntersectionObserver still handles counter animation on the inner `[data-count]` elements — untouched.

**Second blocker (GitHub distribution) — NOT yet fixed.** Requires GitHub Pages configuration + README link. Deferred to future session.

## 3. React vs. Vercel Discussion

**User question:** Why not use React and publish on Vercel or Render instead of self-contained HTML?

**Answer (not implemented — discussion only):**

The HTML-first approach (oracle-weave skill) was right as a first step — zero setup friction, proves the concept immediately. But React + Vercel is the correct end state for the stated goal.

**Why React + Vercel is better for the actual goal:**
- Solves GitHub distribution problem at the root (live URL, not raw HTML)
- `kilima-career-dashboard.vercel.app` is what a recruiter clicks from LinkedIn or README
- Demonstrates React skill rather than raising the question "did Claude write it?"

**The real tradeoff:**
- Build with AI now → live URL immediately, but "did you write the React?" question moves up one level
- Build it yourself as you learn React → takes longer, but portfolio piece and skill are the same thing — you can say "I built this" and mean it in the way a Full Stack role evaluates it

**Decision deferred** — rebuild as React app is the right next step after React fundamentals are refreshed.
