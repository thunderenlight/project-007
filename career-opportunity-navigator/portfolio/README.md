# portfolio/

## Purpose
Tracks portfolio projects — ideas, active builds, and completed work.

## Why This Exists
Portfolio development is not accidental. Without deliberate tracking, it becomes something you intend to do but never consistently do. This directory makes it a managed practice with visible status — not something you hope happens alongside project work.

## Industry Parallel
Product teams use roadmaps and Kanban boards to track feature work. This directory is your personal Kanban for portfolio projects. Engineers at top companies treat their personal projects as seriously as their professional ones.

## Directory Structure

```
portfolio/
├── ideas/          ← Project ideas not yet started (capture them before they disappear)
├── in-progress/    ← Active builds with weekly status notes
└── completed/      ← Finished projects with GitHub links and outcomes
```

## Project File Template

Create one file per project:

```markdown
# [Project Name]

**Status:** Idea / In Progress / Complete
**Target Roles:** [Which Tier 1/2 roles this helps]
**Tech Stack:** [Technologies]
**GitHub:** [Link when created]
**Live URL:** [Link when deployed]
**Started:** [Date]
**Completed:** [Date]

## Description
[What it does, in plain English]

## Why This Project
[Which evaluation dimensions it improves]

## Progress Notes
[Weekly updates as you build]

## What It Demonstrates
[What a hiring manager sees when they look at it]
```
